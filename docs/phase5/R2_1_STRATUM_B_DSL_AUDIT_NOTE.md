### §3.5 Dim (b) audit caveat (load-bearing)

**Factor-compute-level PASS verifies the factor function itself is lookahead-free**. It does NOT verify how the strategy DSL uses the factor (e.g., a strategy could reference a factor at a wrong lag, compare future-bar values, or use the factor in an arithmetic operation that introduces lookahead at the strategy interaction layer). That intent-layer check requires DSL entry/exit conditions, which are **INDETERMINATE-DSL-UNAVAILABLE** for these 4 candidates (see §5).

Dim (b) PASS therefore narrowly verifies upstream factor integrity, not downstream strategy-level integrity. The R2.1 SEAL artifact should not be read as "no lookahead defect possible" — it is read as "no lookahead defect detectable at factor-compute layer given the available data".
